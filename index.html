How a change flows

  1. Product leadWrites the brief: who it is for, the appetite, the no-gos.
  2. DesignerStoryboards the journey and mocks up two or three options at different stars.
  3. FounderGets one queue item that fits one sitting, and picks.
  4. BuilderBuilds one decided issue, in its own worktree.
  5. ReviewerReads the diff and the rendered screens against the brief.
  6. IntegratorThe only role that merges. Merges nothing while a red issue is open.
  7. Ops watchEvery night, checks the Pages deploy is green and every link on the site resolves. A failure opens one red issue; the next green run closes it.

The check is in this repo and can be read: check_site.py, ops-watch.yml.

What this is not

No evidence that anyone besides the founder wants this.

There is none yet, and this site cannot produce any. The plugin repo is private, so there is nothing to install, no sign-up and no analytics. Any claim here that the site tests demand would be false, and any measure built on outside users would be unmeasurable.

That question stays open. It is not what this bet answers.
