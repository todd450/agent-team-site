Founding Agents

An agent team that proposes, builds and merges one change at a time.

This site is the team's test bed, not a launch. The plugin repo is private, so there is nothing here to install and nobody but the founder is meant to read this. The site's job is to give build and propose real changes to run on, in public, where every claim has to survive a reader who can check it.

Status as of 26 October 2026. Build steps 1 and 2 are done; steps 3 and 4 are running on this site. Step 1, branch protection on main, closed 24 Oct: main requires a pull request with admins included, and a builder session's push was blocked. Step 2, ops watch's nightly site check, closed 25 Oct: it was installed by setup in PR #2, its first run on GitHub was green, and a red run by hand opened issue #3, kept it current and closed it on green on 26 Oct. Step 3, build running to merge on three to five real site issues, and step 4, propose running on this brief and one more, are both open.

Written by hand from this repo's issues and merged pull requests, which are public and can be checked against this paragraph. No open red issue at the time of writing.

The four costs

Each of these is real in one founder's history, measured in that founder's own repositories and recorded in the design doc. The doc is in a private repo, so these carry a date and no link.

  • Volume nobody can read. 5,410 commits in under five months. Recorded 26 Oct 2026
  • Work undone as fast as it was done. 32 removal commits deleted 61,365 lines in eight days. Recorded 26 Oct 2026
  • Sweeping up after the fact. 731 bug-sweep and audit commits. Recorded 26 Oct 2026
  • Nobody watching. A nightly off-site backup failed all 28 of its runs, unnoticed. Recorded 26 Oct 2026

How a change flows

idea → product lead's brief → designer's mockups → one queue item → founder decides → builder, in its own worktree → reviewer → integrator merges

The integrator is the only role that merges. Ops watch runs a check every night; while a red issue is open, nothing merges at all. The check is in this repo: check_site.py and ops-watch.yml.

What this is not evidence of

That anyone besides the founder wants the plugin or this site. There is no evidence of that yet and this site cannot produce any: the plugin repo is private, so there is nothing to install. Any claim here that the site tests demand would be false. That question stays open and is not what this bet answers.

The record of this build

  • 24 Oct — protection on main blocked a builder session's push before the builder knew the rule existed. It worked, and it worked by surprise.
  • 25 Oct — the brief's premise changed after it had already been decided go. The 24 Oct decision carried a target of five outside users; the plugin stayed private, so the target became unmeasurable. The brief was rewritten rather than quietly kept.
  • 25 Oct — build and propose had run only on throwaway repos. Steps 3 and 4 were not done, and this site is the first real thing to run them on.
  • 26 Oct — the brief nearly shipped a rule that would have frozen every merge: "every claim links to a file or merged PR" in the private plugin repo. Ops watch crawls every link with no credentials, so each one would answer 404 and open red. Caught before it reached the page.

How we will know it worked

  • Merges not made by the integrator: 0.
  • build ran to merge on three to five real site issues.
  • propose reached the founder as one queue item per issue, each fitting one sitting.
  • Lines deleted within two weeks of being written falls.
  • The oldest open red issue is hours old, not days. Issue #3 was opened and closed inside a day; that is the bar.
  • Not a measure: stars, traffic, or anyone installing anything.
