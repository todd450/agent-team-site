How a change flows

  1. Product leadWrites the brief: who it is for, the appetite, the no-gos.
  2. DesignerStoryboards the journey and mocks up two or three options at different stars.
  3. FounderGets one queue item that fits one sitting, and picks.
  4. BuilderBuilds one decided issue, in its own worktree.
  5. ReviewerReads the diff and the rendered screens against the brief.
  6. IntegratorThe only role that merges. Merges nothing while a red issue is open.
  7. Ops watchEvery night, checks the Pages deploy is green and every link on the site resolves. A failure opens one red issue; the next green run closes it.

The check is in this repo and can be read: check_site.py, ops-watch.yml.

The record of this build

Written as it happens, not afterwards. It is the only proof this site can offer, so it keeps the parts that do not flatter the team.

  • 26 Oct 2026 · the rule that would have frozen every merge

    The brief nearly shipped the rule "every claim links to a file or merged PR in the plugin repo". That repo is private and the nightly check crawls every link with no credentials, so each link would answer 404, open red, and stop the integrator merging anything. Replaced before it reached the page: claims link to this repo's own public files, PRs and issues, or they carry a date and no link.

  • 26 Oct 2026 · the order bent

    This brief was played by hand on 24 Oct, before propose existed as a run. The product lead rewrote it on 26 Oct, so the lane's first real run is a re-run of an already-decided brief. The 24 Oct decision and the 25 Oct change stay in the issue's comments rather than being tidied away.

  • 25 Oct 2026 · the premise changed after the decision

    The site was decided go on 24 Oct with a target of five outside users in four weeks. The plugin repo stayed private, so the target became unmeasurable and the launch page had no reader. The bet was cut to a test bed at one day instead of being kept alive on a target nobody could check.

  • 25 Oct 2026 · roles that did not exist yet

    build and propose had run only on throwaway repos. Steps 3 and 4 had no real product to run on, which is the job this site took.

    Branch protection on main blocked a builder session's push before the builder knew the rule existed. It is the behaviour the team wanted, found the way nobody plans for.
